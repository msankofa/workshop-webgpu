TERRAIN
1. HIGH: A shared 2 ms budget is soft when one BVH costs 3-4 ms. Install -> batch -> cascade -> collider ordering can starve collision under sustained arrivals. Prioritize body-critical collision/coverage and guarantee fair progress elsewhere, with an explicit one-item overrun policy. 2. HIGH: The no-hole claim holds only for an INSTALLED mesh waiting for batching. A raw inbox result has no mesh. Keep valid old coverage/collision until replacement readiness, and base near/far masks on committed residency. Source changes need a valid fallback because old-source geometry may be wrong. Test walking, teleports, source changes and delayed collision readiness.
3. HIGH: Bound completed-result bytes as well as in-flight jobs. A cap of 12 neither prevents simultaneous completions nor bounds an inbox if new jobs dispatch faster than integration. Track queued keys to prevent duplicates, identify jobs by system/epoch/key or request ID, validate at enqueue AND commit, and clear/release state on rebuild/dispose/worker failure. pendingBuildCount and unload-idle checks must include queued integration. 5. Select work globally across systems/stages rather than draining each inbox in fixed order. Include disposal, bounds, batch growth/copies and subsequent GPU uploads in measurements: installation changes can move a spike into renderer.render. Transfer worker buffers and consider returning bounds. Instrument queue bytes/age, max item duration, overruns, stale drops and collision-ready distance first. RENDER SUBMISSION
1. HIGH: A's sum(indexCount) * maxInstancesPerVariant draw is bounded by CAPACITY, not live counts.

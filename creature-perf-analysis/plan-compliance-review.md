## Correctness findings

**No aliasing bugs found.** Specific audits the plan flagged:

1. **`armRestTarget` return liveness across the combat double-call (2.1 audit point 1):** `windupBack = armRestTarget(arm)` (2887) aliases `_restWorld`. In the `windup` branch it is overwritten then consumed by `lerpVectors` in the same statement pair (2891–2893). In the `recover` branch `armRestTarget` is called again (2896) — same buffer, but `windupBack` is dead in that branch; `strike` (the other `lerpVectors` operand) is a fresh clone. In the `else` branch it is `.copy`'d immediately (2898). No overlap of two live `_restWorld` values.
2. **`constrainArmTarget` `target === scratch` (2.1 audit point 2):** `target` is always `arm.desiredTarget` (2900, 2961), never `_localScratch`; `target.copy(localToWorld(local))` at 2844 reads the scratch after its in-place mutation — safe by construction. Same shape holds for `constrainArmPoint` (`point` is a chain-owned `points[i]`, never `_pointScratch`).
3. **`KinematicChain.solve` does not mutate root/target:** verified (675, 695, 701 — only `.copy(root)` / `.copy(target)` into its own points; `distanceTo` reads). Passing `arm._shoulderWorld` as root is safe; `_shoulderWorld` is not overwritten between 2987 and its last use at 3033 within an arm iteration.
4. **Pooled hull lifetime (2.2):** `_hullOut` holds references into `_groundedBuf`; both are fully consumed inside `physicsStep` before any other creature's step, and the debug branch deep-copies (2736). No escaping reference found.
5. **1.2 flag discipline:** set on both creatures of every push; cleared per sub-step before physics; a stale `true` on a temporarily non-sim creature is provably cleared before it can ever be consumed. Not a bug.

Advisory (non-bugs, worth knowing):
- `arm._carryWorld` is an implementation addition (not in the plan's buffer list) used only at 3027 — correct, but keep it in mind if the carry path is refactored.
- 1.4's cached foot quaternion can be transiently stale if the terrain function itself changes under a planted foot (procedural-terrain slider sessions); resolves as soon as the foot steps. Same staleness class as `leg.end`.
- 3.1's CPU field and the grass GPU texture share one Float32Array; any future code that regenerates `loadedMap.heightTex` must also refresh or re-alias `cpuHeightField`.

## Verdict

**Compliant.** All nine claimed items (1.1–1.6, 2.1, 2.2, 3.1) are implemented and present in the
working tree. Deviations from the plan's literal wording are confined to: accessor-over-cached-field
instead of replaced call sites (1.1), `Cached`-suffixed field names (1.3), pooled-buffer-reset
placement (2.2), and aliasing the existing grass bake instead of a second bake (3.1) — all benign,
and the 3.1 and `_carryWorld` deviations are improvements. Every "leave alone" instruction was
honored, 3.2/3.3/3.4 and the Deferred track are genuinely absent, and no aliasing or correctness
bug was found.
